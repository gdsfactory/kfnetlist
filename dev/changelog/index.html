Changelog

0.5.0

  • PWL sources in every grammar — a PWL waveform has inline points or a file (Waveform.file, proto field 4; a pathlib.Path in Python, stored POSIX). Native forms: SPICE PWL(...) / Xyce PWL FILE "w.txt" (also written for ngspice and HSPICE), Spectre type=pwl wave=[...] / file="w.txt" (Cadence vpwlf/ipwlf), Verilog-A and SystemVerilog vpwl #(.wave('{...})) / (* pwl_file = "w.txt" *) vpwl .... Every SPICE grammar reads source functions with a space before ( (PULSE (0 1 ...)); SystemVerilog reads '{...} assignment patterns.
  • OS-agnostic file paths — kfnetlist.morphnet.netlist.paths (posix_file, resolve_file, is_absolute) and Rust kfnetlist_schema::paths give the same answers on every OS: \ or / separators, /x, C:\x, C:x and \\server\share absolute everywhere, ./.. resolved lexically and never above a root, a relative path joined to an optional base. One shared case table (tests/data/path_cases.json) tests both.
  • Simulation stimuli — simulation.proto gains Stimulus (dc, AC magnitude and phase, Waveform of kind PULSE/SIN/EXP/SFFM/PWL) in Simulation.stimuli; each V/I source points to its stimulus in properties["stimulus"]. Shared value types (PrefixedValue, Expression, ParameterValue, ...) move to value.proto (no Rust path or Python name changes). Every parser reads its language's own source syntax, every writer writes it: SPICE DC/AC/PULSE(...), Spectre vsource type=pulse ..., Verilog-A/SystemVerilog LRM Annex E primitives (vpulse, vsine, ...). See the API reference.
  • A source's value parameter is gone: SPICE DC 0.9 AC 1 used to read back as value=1; .gsch sources have no params.
  • SPICE parsers read PULSE(...)-style waveforms, {...}/'...' element values, and a bare R/C/L value as a parameter reference unless a .model of that name is in the deck (R1 a b rload).
  • Spectre reads simulator lang=spice sections and keeps quoted strings.
  • Verilog-A reads expressions in #(...), module m;/module m ();, attributes, net initializers (nodesets), paramsets of primitives; writes a .model device by its model name with a paramset, ground from the netlist's ground net, and SPICE libraries and foreign inline code as module attributes (no warning, nothing dropped). Identifiers and quoted strings are kept instead of read as empty values.
  • One-pin nets survive every parser; an unconnected pin is written on its own node nc_<instance>_<pin> instead of ?.
  • Every SPICE-family and Spectre parser takes a deck's own elements as the top circuit (__top__), not the last subcircuit.
  • tests/morphnet/test_gsch_conversions.py converts every .gsch fixture to ngspice, HSPICE, Xyce, Spectre, Spectre-SPICE and Verilog-A and reads it back; a conversion passes only when no field is missing.
  • gsch — parse_gsch(), read_gsch() and write_gsch() in kfnetlist.morphnet.netlist read and write gdsfactory+ .gsch schematics (Mosaic and Livewire JSON).
  • models.nyanlib libraries become LIB/INCLUDE directives, written as .lib/.include at the top of SPICE netlists and as include "p" section=s in Spectre. sim (ngspice, xyce, vacask) and corners choose the model entry and library section.
  • The simulation view follows nyancad's netlister: model entries, pins, parameter expressions, sources and waveforms. It exports the circuit, not the simulator scaffolding (.end, analyses, load *.osdi).
  • Positions, wires, polylines and port markers survive write_gsch.
  • Source props (role="source") are editable: an edit reaches the .gsch props and the SPICE output. An edit to a derived or computed parameter (a model params expression, a model param named like the prop it reads, or an expression reading such a prop) raises ValueError from write_gsch, naming the props to edit. Model prop defaults are written once edited.
  • Limits: a file written from a non-gsch source has no Mosaic wires. See the API reference.
  • Inline nyanlib code blocks become Netlist.macros (see Macros).
  • Expressions — ParameterValue gains an expression variant, an Expression tree (literal, reference, unary, binary, call, ternary, or raw text no grammar parsed). parse_expression() / format_expression() in kfnetlist.morphnet.netlist.expression read any dialect's text and print the canonical form (0.13 * 1e-6). The .gsch, SPICE, HSPICE, Xyce, Spectre and SystemVerilog parsers produce it; the properties["expr"] text of earlier development builds is gone. A model parameter such as w = width * 1e-6 is an expression over the source props, not a fixed number. ^ is XOR in SystemVerilog, so text with ^ stays raw. JSON and YAML name the set node directly ({"binary": {...}}) in Python and Rust alike, so ProtoNetlist.from_json(netlist.to_json()) loads expression parameters. format_expression() raises ValueError for an unknown dialect; an expression with no node is not written. Through the kfnetlist bridge an expression parameter is a string setting with its canonical text, and its tree rides in info["__morphnet__"]: unchanged text restores the tree, edited text is parsed again (raw when it does not parse). Other kfnetlist string and bool settings become raw expressions kept verbatim (model="nch-lvt" stays nch-lvt).
  • Macros — a new Macro message (name, language, body, properties) on Netlist.macros and Circuit.macros carries verbatim blocks. Writers print a body when their dialect takes its language (Spectre wraps SPICE bodies in simulator lang=spice); otherwise they write a skipped macro <name> (<language>) comment and warn. VACASK takes none. The kfnetlist bridge keeps both lists in info["__morphnet__"]. Equal macros are kept once; same-named blocks with different code are all kept (parse_gsch warns). A nyanlib code entry with no language is spice.
  • Lossless bridge — morphnet.to_netlists() / from_netlists() keep what kfnetlist.Netlist has no field for. New Netlist.directives (file directives) and Netlist.info (metadata) hold it. Both are excluded from equality, and so are instance info keys that start with __: an instance with only such keys now equals one without. This is a behavior change for instance equality.
  • Writers:
  • Spectre include "path" section=name [lang=x] is supported.
  • The Xyce writer emits PARAMS: on subcircuit headers and X calls.
  • SPICE subcircuit parameters moved from body .param lines to the .subckt header line.
  • The SPICE and Spectre writers handle expression parameters, device prefixes and the ground net.
  • The VACASK dialect of the Spectre writer puts subcircuit parameters on a parameters line in the body, as nyancad does; plain Spectre keeps them on the subckt line.
  • Output changes for existing users:
  • morphnet to_json() / to_yaml() leave out unset (null) fields and empty macros, as the Rust schema does, so a document that uses no new field loads in older kfnetlist readers. Pass exclude_none=False for the old output.
  • kfnetlist string and bool settings now reach SPICE and Spectre output as parameters (mode=fast, on=true); they used to be dropped.
  • The SPICE writers prepend the element letter, or X for a subcircuit call, to instance names that lack it (load is written Rload).
  • JSON from the bridge carries info and directives on netlists and instances. kfnetlist readers older than this release reject it (their deny_unknown_fields schema does not know these keys).
  • The document header (name, properties, external circuits, libraries, simulation) is kept on every cell, so from_netlists() of a subset or with another toplevel keeps .model cards and ground_net.
  • A port net named after its port (a bridged netlist names every net) keeps its name: NetlistDocument.from_netlists() writes it as a named net, and only an unnamed port net uses the plain ports: {o1: mmi,o1} form.
  • A present but non-object info["__morphnet__"] raises ValueError (info['__morphnet__'] must be an object) instead of being dropped.
  • Circuit.buses and __-prefixed properties the bridge does not own (on instances, circuits and connections) round-trip through info["__morphnet__"]. A bus is restored while an unnamed net still has its members; its member nets stay plain nets in kfnetlist. Foreign properties of a connection come back on the connection with the same endpoints; a net edited to connect different pins loses them.
  • Writers print expression parameters in canonical form, wrapped per dialect: {…} for ngspice and Xyce, '…' for HSPICE, bare for Spectre, VACASK, SystemVerilog and Verilog-AMS. A bare name or number is never wrapped; text no grammar parses (x^2) is wrapped as a k=v value unless already wrapped, and a positional value (DC 1 AC 1) stays verbatim. An empty value is not written. Xyce expressions now carry braces, and a .gsch prop written {vdd} reaches VACASK as vdd.
  • The SPICE-family and Spectre parsers keep expression values ({a*b+1}, 'a*b+1', Spectre a*b+1), where they dropped them. Written back, the ngspice and Xyce text is {a * b + 1}: braces and canonical spacing, so {2*x} is written {2 * x}. An identifier value (l=a) is written as l=a, where it was written l=0. .option, analysis, .meas and .ic values (errpreset=moderate) are kept, where they were empty. A .param directive keeps its text in the dialect it was parsed from.
  • A source prop of a .gsch device is left out of the SPICE, Spectre, VACASK, SystemVerilog and Verilog-AMS output as a device parameter; references to it are replaced by its value.
  • A bridged parameter keeps its properties (role) when its setting is edited, and text the bridge reads back as raw is parsed again when it can be.
  • The key order inside .gsch entries is not preserved through the kfnetlist bridge: write_gsch output is JSON-equal, not text-equal.

0.4.1

  • SystemVerilog — parse_systemverilog() / write_systemverilog() in kfnetlist.morphnet.netlist read and write structural SystemVerilog (SystemVerilog 3.1a, Annex A) with an LALR Lark grammar:
  • ANSI and non-ANSI ports, parameter/localparam, net declarations;
  • instances with named, positional, .name, .* and empty connections;
  • assign a = b; / alias net merges.

Behavioral code is kept as text in behavioral_block_N circuit properties and written back by the SystemVerilog writer. - Waveguide terminals by name — every parser marks terminals named o1, o2, ... as SignalDomain.WAVEGUIDE; e1, ... and unprefixed names are ELECTRICAL. A connection is waveguide when any terminal on its net is. Parsed connections are now always ELECTRICAL or WAVEGUIDE instead of UNSPECIFIED. The helper is kfnetlist.morphnet.netlist.net_utils.domain_of(). - Conversion fixes: - The SPICE and Spectre writers use the device pin order (d g s b for a MOSFET) for built-in devices that have no external-circuit declaration, which is the case after parsing Verilog-AMS or SystemVerilog. SPICE used to write ? ? and Spectre wrote the pins in net order. - The Spectre parser picks the device from the master: a subcircuit defined in the deck, or a built-in master like capacitor, wins over the instance-name letter (I1 (...) inverter was read as a current source). A subcircuit named like an analysis (dc) is an instance, not an analysis. - The Spectre-SPICE parser names the pins of instances whose subcircuit is defined in the other language section (they used to be p0, p1, ...). - Docs — new notebooks Parsing netlist formats (an example netlist per format, electrical and photonic) and Converting between formats (pairwise conversions, a 7 × 7 conversion matrix, a photonic MZI round trip). The MZI notebook uses o1...o4 terminals.

0.4.0

  • Loads on macOS 27 (#31) — rustc strips macOS release builds with rust-objcopy, which left the extension's LINKEDIT string pool misaligned, and macOS 27's dyld refused to load it. .cargo/config.toml now skips that strip on macOS (also in the sdist), and the release workflow rejects any misaligned macOS wheel.
  • Bidirectional netlist format conversion — morphnet's source is vendored as kfnetlist.morphnet. Its runtime dependencies (lark, protobuf, pydantic, pydantic-yaml) become kfnetlist dependencies. It provides Lark parsers and writers for SPICE, HSPICE, Xyce, Spectre, Spectre-SPICE and Verilog-AMS, plus the programmatic circuit builder (morphnet.circuit(), subcircuit(), connect(), ...). morphnet.from_netlists() / to_netlists() bridge to Netlist. The native netlist and schema classes still import none of these.
  • One naming everywhere: Netlist → Circuit → SubCircuit. The container, circuit definition and instance have the same names in circuit.proto, Rust, the PyO3 schema classes, the PIC document model and kfnetlist.morphnet:
Layer Before Now
proto messages Circuit, Module, ModuleReference, ExternalModule Netlist, Circuit, SubCircuit, ExternalCircuit
proto fields top_module, modules, ext_modules, module_references, module_name top_circuit, circuits, ext_circuits, subcircuits, circuit_name
kfnetlist_schema ProtoCircuit (container), ProtoModule, ProtoModuleReference, ExternalModule ProtoNetlist, ProtoCircuit (definition), ProtoSubCircuit, ExternalCircuit
PIC documents TopLevelModule, Module, Instance NetlistDocument, CircuitDocument, SubCircuitDocument (YAML keys unchanged)
conversions to_proto_circuit(), from_proto_circuit() to_proto_netlist(), from_proto_netlist()
morphnet Circuit, Module, ModuleReference, module(), module_reference(), ext_module() Netlist, Circuit, SubCircuit, circuit(), subcircuit(), ext_circuit()
  • The wire format is unchanged (same field numbers), so protobuf bytes from earlier versions decode as before.
  • Old keyword arguments, dict, JSON and YAML keys still load, with one DeprecationWarning. Old getters and old class/function names remain as deprecated aliases. ProtoCircuit is the exception: it now names the circuit definition, and container data passed to it is rejected.
  • morphnet JSON and YAML use the schema names, so ProtoNetlist.from_json(netlist.to_json()) loads them.
  • One circuit schema — circuit.proto and the new simulation.proto now follow morphnet's schema (renamed as above), shared by Rust and Python. It adds simulation, directives, external libraries and Terminal.discipline. It removes uid, Terminal.cross_section and the string domain fields, renames terminal to terminals, and replaces the instance parameter_values/parameter_overrides with parameters.
  • Backward compatible: the old keyword arguments, dict and JSON keys are still accepted with a DeprecationWarning. Removed values are kept in properties["__<field>__"] (or in parameters), and deprecated getters read them back.
  • Documents encoded by earlier versions (NetlistDocument.to_proto()) decode unchanged.
  • Not readable: hand-built ProtoSubCircuit bytes that use the old parameter_values (field 10) or parameter_overrides (field 20).
  • NetlistDocument.to_proto() now encodes nets in morphnet's named-net form, which earlier versions cannot read.
  • SI prefixes — PrefixedValue.prefix is applied when converting to Netlist settings (1k becomes 1000.0).
  • Zero Python runtime dependencies — protobuf and YAML parsing now run entirely in the native extension. The duplicate Python schema converters and generated protobuf module were removed. Pydantic interoperability remains available when applications install Pydantic separately.
  • Pure connectivity core — PIC documents, YAML, and protobuf moved from kfnetlist-core into the new kfnetlist-schema crate.
  • Instance removal no longer creates empty nets when an absent or isolated instance is removed.
  • Selective instance flattening — an explicit instance_cell_map now selects which starting instances may flatten, in addition to supplying their cell names. Omitted instances remain intact throughout recursion, including placed instances of the same cell. None considers all instances; {} selects none. Descendants of selected instances inherit eligibility, subject to cells / exclude. sub_instance_cell_maps remains a cell-name lookup. This changes the previous lookup-only behavior of instance_cell_map.
  • Instance metadata — NetlistInstance.info and PlacedInstance.info carry JSON-compatible dictionaries, accepted through keyword-only info= constructor and create_inst() arguments. Extraction copies named kfactory instances' metadata. Metadata survives serialization, normalization, placement conversion, and child promotion during flattening. Empty metadata is omitted from output, and existing payloads without info remain readable.
  • Netlist.flatten() — hierarchical flattening: replace instances by the contents of their own cell's netlist, rewiring the parent's nets through the sub-cell's ports. Selectable per cell (cells / exclude), recursive by default, and placement-aware on PlacedNetlist (each inlined placement is composed with the placement of the instance it came from). kfnetlist.flatten_netlists() applies it to a whole {cell name: netlist} mapping, and extract(..., flatten=...) does it as part of extraction.
  • Netlist.flatten_instances() renamed to remove_instances() — the old name still works but raises a DeprecationWarning. It never inlined anything: it deletes instances and merges the nets they touched, which the new flatten() would otherwise be confused with.
  • Optional net names — Net carries a name, set at construction (Netlist.create_net(..., name=...), Net(..., name=...), both keyword-only) and copied by Netlist.add_net(). The name survives serialization, remove_instances(), normalize() and flatten(); a merged net keeps the name of the lowest-indexed net that had one. Names are metadata, not identity: equality, hashing and ordering ignore them, so connectivity comparison is unchanged. A named net is written as {"name": ..., "members": [...]}; an unnamed net keeps the historical bare JSON array, and reading accepts both. The object form requires members and rejects unknown fields. Forward incompatibility: a reader released before this change expects a net to be an array and rejects any document containing a named net. Names travel with the netlist JSON only — the PIC-document (YAML/protobuf) net representation has no name slot yet, so Module.from_netlist() still drops them.

0.2.0

  • find_net_difference() (renamed from find_open_nets) — compares two netlists by symmetric difference on their sorted nets, returning {"missing": [Net, ...], "extra": [Net, ...]} instead of the previous flat list. The new structure distinguishes nets absent from the layout (missing) vs. unexpected nets (extra).
  • normalize() replaces lvs_equivalent() — the method name was changed to better reflect its purpose: fold equivalent ports into canonical names and merge nets sharing a canonical reference. The API and behaviour are unchanged.
  • Python 3.14 support — classifier and CI testing added.

0.1.5

  • L2N parsing — parse_l2n() and l2n_to_json() convert a klayout LayoutToNetlist to a JSON-serializable dict (or string) with optional hierarchy flattening and layer/instance filtering
  • Geometric short detection — detect_shorts() finds polygon overlaps between electrically distinct nets on the same layer
  • Open detection — Netlist.detect_opens() finds unconnected ports and singleton nets; Netlist.find_net_difference(reference) compares against a reference netlist to find missing and extra nets

0.1.0

Initial release.

  • Rust-backed core types: Netlist, Net, NetlistPort, PortRef, PortArrayRef, NetlistInstance, NetlistArray
  • Full JSON/dict serialization on all types
  • Pydantic v2 integration (__get_pydantic_core_schema__)
  • Netlist.normalize() for folding electrically-equivalent ports
  • Netlist.flatten_instances() for merging sub-cell instances
  • PortCheck bitmask and check_connection() for geometric port comparison
  • kfnetlist.extract subpackage for hierarchical netlist extraction from layout cells
